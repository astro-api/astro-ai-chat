# Остановка генерации и редактирование сообщения

**Дата:** 2026-06-22
**Статус:** design approved

## Проблема

Сейчас нельзя прервать генерацию ответа AI. Пока идёт стриминг, поле ввода
полностью заблокировано (`InputBar` `disabled` при `isStreaming`), а сетевой
запрос к LLM-провайдеру идёт до конца — токены тратятся даже если ответ уже
не нужен. Также нет способа исправить только что отправленный вопрос, если
ответ оказался не тем, что ожидалось.

## Цель

1. Кнопка «Стоп», прерывающая генерацию ответа (и сетевой запрос к провайдеру).
2. Возможность отредактировать **последнее своё** сообщение **после остановки**
   ответа — с удалением прерванного ответа и перезапросом.

## Согласованные решения

- **Поведение «Стоп»:** прерванный ответ сохраняется в истории с пометкой
  «⏹ остановлено пользователем». Но если пользователь затем редактирует свой
  запрос — этот прерванный ответ удаляется из истории.
- **Редактирование:** доступно только для последнего своего сообщения и только
  после остановки ответа (когда ответ не дошёл до конца). Отредактировал →
  прерванный ответ удаляется, запрос отправляется заново.
- **Механизм прерывания:** `AbortController`, переданный в `streamText({ abortSignal })`.
  Это рвёт и сетевой запрос к LLM, экономя токены.
- **Развязка редактирования:** отдельный IPC `chat:edit-last` (не флаг в `chat:send`),
  чтобы `chat:send` оставался простым.
- **Вид кнопки «Стоп»:** залитый квадрат с лёгкой пульсирующей анимацией.

## Архитектура

### 1. Модель данных (`src/main/db/`)

- В таблицу `messages` добавляется колонка
  `interrupted: integer('interrupted', { mode: 'boolean' })` (nullable,
  по умолчанию `null`/`false`).
- Новый SQL-файл миграции Drizzle: `ALTER TABLE messages ADD COLUMN interrupted INTEGER`.
  Миграции выполняются автоматически на старте (`runMigrations()`).

### 2. Main-процесс (`src/main/ai.ts`)

**Реестр активных стримов.**
- Модульный `Map<string, AbortController>` — ключ `chatId`.
- В начале `sendMessage()`: создать `AbortController`, положить в Map по `chatId`,
  передать `controller.signal` в `streamText({ abortSignal: controller.signal })`.
- В `finally`-блоке: удалить контроллер из Map (`activeStreams.delete(chatId)`).

**Обработка прерывания.**
- При срабатывании `abortSignal` цикл `for await (...result.fullStream)` бросает
  `AbortError`. Ловим его в отдельной ветке (проверка `err?.name === 'AbortError'`):
  это **штатная остановка, не ошибка** — НЕ прогоняем через `friendlyError`,
  НЕ дописываем `⚠️` к тексту.
- Если накопленный `fullText` непустой — сохраняем сообщение ассистента в БД
  с `interrupted: true`. Если пустой — не сохраняем ничего.
- В любом случае шлём `chat:stream-end`.

**Функция `abortStream(chatId)`.**
- `activeStreams.get(chatId)?.abort()`. Идемпотентна, безопасна если контроллера
  нет (стрим уже завершился — `chat:stop` тихо игнорируется).

**Функция `editLastMessage({ chatId, newMessage, window })`.**
- В одной транзакции удаляет: (а) последний прерванный ответ ассистента
  (`interrupted = true`), (б) последнее пользовательское сообщение чата.
- Затем вызывает обычный `sendMessage()` с `newMessage`.

### 3. IPC (`src/main/ipc.ts` + `src/preload/index.ts`)

- `chat:stop` → `ipcMain.handle('chat:stop', (_e, chatId) => abortStream(chatId))`.
- `chat:edit-last` → `ipcMain.handle('chat:edit-last', (event, { chatId, message }) => ...)`,
  по аналогии с `chat:send` (получает окно из `event.sender`, оборачивает в try/catch
  с `chat:stream-error`).
- `preload`:
  - `stopMessage: (chatId) => ipcRenderer.invoke('chat:stop', chatId)`
  - `editLastMessage: (chatId, message) => ipcRenderer.invoke('chat:edit-last', { chatId, message })`

### 4. Renderer

**`useChat` hook (`src/renderer/src/hooks/useChat.ts`)**
- Тип `Message` расширяется опциональным полем `interrupted?: boolean`;
  `loadMessages` прокидывает его из записи БД.
- Новое состояние `editingContent: string | null`.
- `stopMessage()` → `window.electronAPI.stopMessage(activeChatId)`. Дальнейшее
  завершение доезжает штатно через `chat:stream-end` (хук перезагрузит сообщения,
  прерванный ответ уже в БД с флагом).
- `startEdit(content)` → ставит `editingContent`, фокус управляется в `InputBar`.
- `cancelEdit()` → `editingContent = null`.
- `editLastMessage(newText)` → `window.electronAPI.editLastMessage(activeChatId, newText)`,
  затем оптимистично: `setIsStreaming(true)`, очистка стрим-буфера (как в `sendMessage`),
  сброс `editingContent`.

**`InputBar` (`src/renderer/src/components/InputBar.tsx`)**
- Поле ввода остаётся **активным** во время стрима (можно печатать), но
  отправка по `Enter`/клику заблокирована пока `isStreaming`.
- Кнопка переключается по состоянию:
  - `isStreaming === true` → иконка «стоп» (`Square` из lucide-react) с лёгкой
    пульсирующей анимацией; клик вызывает `onStop()`.
  - `isStreaming === false` → обычная кнопка отправки (текущее поведение).
- Режим редактирования (когда `editingContent !== null`):
  - над полем плашка «Редактирование сообщения · ✕ отмена»;
  - значение поля предзаполнено `editingContent`;
  - отправка вызывает `editLastMessage(newText)` вместо `onSend`.
- Новые пропсы: `onStop`, `editingContent`, `onEditSubmit`, `onCancelEdit`.

**`Message` (`src/renderer/src/components/Message.tsx`)**
- Новый опциональный проп `interrupted?: boolean`. Если `true` и роль `assistant` —
  под текстом приглушённый бейдж «⏹ Остановлено пользователем».
- Новый опциональный проп `onEdit?: () => void` (для последнего своего сообщения) —
  иконка-карандаш (`Pencil`), видна при наведении.

**`MessageList` (`src/renderer/src/components/MessageList.tsx`)**
- Прокидывает `interrupted` в `Message`.
- Определяет «последнее своё сообщение» и условие показа карандаша:
  это последнее сообщение пользователя И нет активного стрима И
  (после него нет ответа ассистента ИЛИ последний ответ `interrupted`).
- Карандаш вызывает проброшенный `startEdit(content)`.

**`Chat` (`src/renderer/src/components/Chat.tsx`)**
- Прокидывает новые колбэки/состояние из `useChat` в `MessageList` и `InputBar`.

### 5. Интернационализация (`src/renderer/src/i18n/`)

Новые строки: бейдж «Остановлено пользователем», плашка «Редактирование сообщения»,
«отмена», подсказка кнопки «Остановить».

## Граничные случаи

- **Стоп до первого чанка** (`fullText === ''`): прерванный ответ не сохраняется;
  индикатор стрима исчезает, остаётся только сообщение пользователя. Карандаш всё
  равно доступен (условие: «после последнего своего нет ответа ассистента ИЛИ он
  `interrupted`»).
- **Стоп во время tool-call** (между раундами `stepCountIs(10)`): `abortSignal`
  прерывает и это; `fullText` = текст до вызова инструмента (может быть пустым),
  обрабатывается тем же путём.
- **Гонка abort / stream-end**: если стрим закончился сам, контроллер уже удалён
  из Map — `chat:stop` тихо игнорируется.
- **Двойной клик «Стоп»**: `controller.abort()` идемпотентен (повторный — no-op).
- **Переключение/закрытие чата во время стрима**: контроллер привязан к `chatId`,
  стрим завершится в фоне и сохранит результат — текущее поведение, не меняем.
- **Summarization**: `maybeSummarize` вызывается до стрима, abort на неё не влияет.

## Вне области (YAGNI)

- Редактирование произвольного сообщения в истории (только последнее).
- Отдельная кнопка «регенерация» ответа.
- Изменение поведения при переключении чатов во время активного стрима.

## Тестирование

- **main:** unit на `abortStream` (есть/нет контроллера в Map), на `editLastMessage`
  (корректное удаление прерванного ответа + последнего юзер-сообщения).
- **Обработка `AbortError`:** проверить, что abort не превращается в `⚠️`-ошибку
  и что `interrupted: true` проставляется только при непустом `fullText`.
- **Ручная проверка:** старт → стоп в середине ответа → бейдж появился → карандаш →
  правка → перезапрос → прерванный ответ исчез из истории.
